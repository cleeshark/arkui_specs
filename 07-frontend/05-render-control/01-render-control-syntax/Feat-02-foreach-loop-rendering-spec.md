## 用户故事

### US-1: ForEach 构造与 keyGenerator

**作为** 应用开发者,
**我想要** 用 `ForEach(arr,itemGen,keyGen?)` 渲染数组,
**以便** 按 key diff 复用/重排子节点。

| AC编号 | 验收标准 | 类型 |
|--------|---------|------|
| AC-1.1 | WHEN dynamic 调用 `ForEach(arr,itemGenerator,keyGenerator?)`（`for_each.d.ts:85-89,107` `@since7`）THEN 返回 `ForEachAttribute`（`@since12` 起，`:29-32`；`@since7-11` 返回 `ForEachInterface`） | 正常 |
| AC-1.2 | WHEN static 调用 `ForEach<T>(arr,itemGenerator,keyGenerator?)`（`forEach.static.d.ets:110-114` `@since23` `@ComponentBuilder`）THEN 返回 `ForEachAttribute`（`:51-59`） | 正常 |
| AC-1.3 | WHEN 省略 keyGenerator THEN 默认 `(item,index)=>${index}__${JSON.stringify(item)}`（`for_each.d.ts:72-74`、`puv2_view_base.ts:1077-1086`，`idGenFuncUsesIndex=true`） | 正常 |
| AC-1.4 | WHEN keyGenerator 生成重复 id THEN TS `forEachUpdateFunction` 抛 `applicationError("Ids generated by the ForEach id gen function must be unique...")`（`puv2_view_base.ts:1115-1117`）；C++ `SetIdArray` 仅保留首现、重复 index 记入 `duplicateIds`（`js_foreach.cpp:188-194`） | 异常 |
| AC-1.5 | WHEN keyGenerator 内 `JSON.stringify` 失败（循环引用等）THEN 抛 `BusinessError(103801)`（`puv2_view_base.ts:1081-1083`） | 异常 |

### US-2: id-based diff

**作为** 应用开发者,
**我想要** 数组变更时按 id diff——新 id 新建、既有 id 重排复用、消失 id 移除,
**以便** 仅更新变化项。

| AC编号 | 验收标准 | 类型 |
|--------|---------|------|
| AC-2.1 | WHEN `CreateTempItems`（`for_each_node.cpp:61-71`）THEN `swap(ids_,tempIds_)`+`swap(ModifyChildren(),tempChildren_)`，Repeat 时另复制 `tempChildrenOfRepeat_` | 正常 |
| AC-2.2 | WHEN `CollectRemovingIds`（`:73-91`）THEN 以 `tempIds_` 种 `tempOldIdsSet_`、建 `oldNodeByIdMap_`，移除仍存于 `ids_` 的 id，余者 `CollectRemovedChildren` 填 `removedElmtId` | 正常 |
| AC-2.3 | WHEN `CompareAndUpdateChildren`（`:94-146`）THEN 建 `newIdsSet`/`oldIdsSet`（`:102,106`）→`swap(children,tempChildren_)`（`:115`）→移除 `tempOldIdsSet_` 中非保留项 `RemoveChild(,true)`（`:117-123`）→`MappingChildWithId`（`:128`）→`ChildrenUpdatedFrom(0)`（`:143-145`） | 正常 |
| AC-2.4 | WHEN `MappingChildWithId` 遇新 id（不在 oldIdsSet）THEN `AddChild(newComp,DEFAULT_NODE_SLOT,false,true)`+`InitDragManager(newComp)`（`:155-168`） | 正常 |
| AC-2.5 | WHEN `MappingChildWithId` 遇既有 id THEN `SetAncestor(nullptr)`（绕过 AddChild 双加守卫）+`AddChild(uiNode,DEFAULT_NODE_SLOT,true)` 重排复用（`:169-179`） | 正常 |

### US-3: 脏标记与 no-op 守卫

**作为** 应用开发者,
**我想要** id 无变化时跳过重渲染、有变化时正确触发父重测量,
**以便** 避免无谓刷新。

| AC编号 | 验收标准 | 类型 |
|--------|---------|------|
| AC-3.1 | WHEN `FlushUpdateAndMarkDirty` 且 `ids_==tempIds_ && !isThisRepeatNode_` THEN no-op 守卫跳过脏标记（`for_each_node.cpp:186`），仅 `tempIds_.clear()` 返回 | 边界 |
| AC-3.2 | WHEN id 有变化 THEN `MarkNeedSyncRenderTree(true)`+`MarkNeedFrameFlushDirty(PROPERTY_UPDATE_MEASURE_SELF_AND_PARENT | PROPERTY_UPDATE_BY_CHILD_REQUEST)`（`:196`） | 正常 |
| AC-3.3 | WHEN `MoveData(from,to)` THEN 重排 `ids_`（`:297-303`）+children（`:305-313`）后置 `MEASURE_SELF_AND_PARENT|BY_CHILD_REQUEST`+`MarkNeedSyncRenderTree(true)`（`:314-315`） | 正常 |

### US-4: 与 Repeat 共用 ForEachNode（已废弃）

> **⚠️ 废弃声明：** `ForEachNode` 经 `isThisRepeatNode_` 标志与 Repeat 共用同一 C++ 类的机制**已废弃**。该共用设计（`GetOrCreateRepeatNode` 复用 `ForEachNode::GetOrCreateForEachNode` + `CompareAndUpdateChildren` 提前 return 走 Repeat 路径）为历史实现耦合，不再演进。Repeat 非虚拟渲染路径的规格详见 **07-05-03 Feat-01**。本 US 不再展开 AC。
